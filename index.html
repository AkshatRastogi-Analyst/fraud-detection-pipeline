Six data checks, one failure

Every run tests the file and saves the results to a table in PostgreSQL. The duplicates check failed, so those rows were removed before the model saw them. Duplicates can land in both the training and test sets and make a model look better than it is.

Two models, one clear winner

Fraud is so rare that a model guessing "legit" every time would score about 99.8% accuracy and catch nothing. So the models are judged on precision, recall and PR-AUC instead.

Limits worth knowing

The 28 model features are anonymised by the data provider, so results can be ranked but not explained in business terms. The model was tested on one random split with an untuned 0.5 threshold. A bank would validate over time and tune the threshold to analyst capacity.
